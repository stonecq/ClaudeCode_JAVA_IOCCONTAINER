# Java 编码规范

实现所有模块时遵循以下规范。

## 语言级别

- JDK 17。可优先使用 record、sealed、switch 模式匹配、`List.of` 等，但以可读性为先。
- 不开 `--enable-preview`。

## 代码风格

- 4 空格缩进；单行不超过 120 字符。
- 类名 PascalCase，方法/变量 camelCase，常量 `UPPER_SNAKE`。
- 不会被重新赋值的局部变量/参数一律 `final`。
- 集合优先不可变（`List.of` / `Collections.unmodifiable*`）。

## 接口与实现

- 面向接口编程；内部可确定的地方用具体实现。
- DTO / 消息模型用 record 或不可变类，避免可变 getter/setter 堆积。

## 注释
本项目为学习项目，注释需详尽清晰，帮助初学者快速理解代码意图与实现思路。核心原则是解释“为什么这样做”，而非重复代码已表达的“做了什么”。具体要求如下：

1. **类注释**：说明整体功能、职责边界及设计思路（如拆分原因、设计模式）。
2. **函数注释**：头部需包含功能说明、参数（`@param`）、返回值（`@return`）及异常（`@throws`）；内部关键步骤需解释算法选择原因及边界/特殊情况的处理逻辑。
3. **成员变量注释**：说明用途、合法值域（取值范围、是否允许为空），非常量变量需补充生命周期或状态变化说明。
4. **常量与枚举**：必须注释业务含义，严禁无注释的魔法数字。
5. **禁止行为**：禁止保留被注释掉的废弃代码（应由版本控制追溯）；禁止编写与代码重复的废话注释；修改代码时必须同步更新相关注释，避免过时注释误导。

## 测试

- JUnit 5 + AssertJ；测试类命名 `XxxTest`。
- 单元测试不访问真实网络/系统文件（用临时目录、Mock WebServer）。
- TDD：先写失败测试，再实现，再确认通过。

## 提交规范

- Conventional Commits：`feat` / `fix` / `refactor` / `test` / `docs` / `chore`。
- 提交粒度小：一个逻辑改动一个提交。
- 仅在用户要求时提交。

## 禁止事项

- 不用 `System.out` 打印（用 SLF4J）。
- 不留死代码 / 注释掉的代码块。
- 不提交 secrets、本地配置（`*.local.*` 已 gitignore）。
- 不写未排期的功能（严格按开发计划推进）。
