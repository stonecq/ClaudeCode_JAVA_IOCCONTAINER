## 1. 项目概述

### 1.1 目标

从零实现一个简易版 Claude Code（agent 命令行/网页工具），具备 agent harness 的核心骨架：自研 IoC 容器、可插拔 LLM、工具系统、agent 循环、多界面适配。定位为**学习型项目**：通过手写核心机制（IoC、工具注册、agent 循环）深入理解 Claude Code / harness 的工作原理，同时以企业级 Java 工程规范组织代码。

### 1.2 非目标

- 不做与商业 Claude Code 的功能对标，仅保留核心骨架。
- 不追求生产级规模，专注可运行、可扩展、可学习。
- 不实现客户端加密、多用户、云端部署等能力。

### 1.3 技术栈摘要

| 项 | 选型 |
| --- | --- |
| 语言 / JDK | Java 17（LTS） |
| 构建 | Maven 多模块（父 pom + 子模块） |
| IoC | 自研迷你 IoC 容器（注解扫描 + 依赖注入 + 生命周期） |
| LLM | 可插拔 `LlmProvider`，内置 `MockProvider` + `OpenAiCompatProvider` |
| 持久化 | 存储抽象 SPI + 文件 JSON 默认实现 |
| CLI | JLine（富交互）+ picocli（命令解析） |
| Web（v2） | 嵌入式 Jetty + SSE |
| 日志 | SLF4J + Logback |
| 打包 | Maven Shade **单 fat-jar**（`mycc-app.jar` 可 `java -jar` 直接运行） |

### 2.2 v1 功能需求

#### FR-1 自研 IoC 容器（mycc-core）

- **FR-1.1 注解**：`@Component`（托管类）、`@Inject`（依赖注入）、`@Tool`（工具注册）、`@Hook`（v2 启用，v1 仅定义注解）。
- **FR-1.2 注解扫描**：`AnnotationScanner` 扫描指定包路径，发现带注册注解的类并生成 `BeanDefinition`。
- **FR-1.3 依赖注入**：**构造器注入优先，字段注入兜底**；注入按类型解析，支持按名称兜底。
- **FR-1.4 生命周期**：v1 仅单例作用域；支持 `init`/`close` 回调（接口或注解），容器 `close()` 优雅释放。
- **FR-1.5 循环依赖**：检测到循环依赖时启动期报错（v1 不做三级缓存/懒加载）。
- **FR-1.6 BeanPostProcessor**：容器在 bean 创建前后调用后处理器列表；**`ToolRegistry`、`HookRegistry` 作为后处理器实现**，实现"加注解即注册"。
- **FR-1.7 门面**：`IocContainer` 提供 `getBean(Class)`、`getBeansOfType(Class)`、`getToolRegistry()`、`start()`、`close()`。

#### FR-2 工具系统（mycc-core 定义 + mycc-tools 内置）

- **FR-2.1 `@Tool`**：注解声明 `name`、`description`；方法参数用 `@ToolParam` 声明描述/必填/校验。
- **FR-2.2 注册**：bean 创建后，`ToolRegistry` 扫描方法上的 `@Tool`，包装为 `ToolDefinition`（name/description/方法句柄/参数 Schema）注册；重名冲突启动期报错。
- **FR-2.3 Schema 生成**：`ParameterSchemaGenerator` 反射生成 JSON Schema（OpenAI 兼容工具格式），支持基本类型、枚举、`@ToolParam` 元数据。
- **FR-2.4 内置工具**（mycc-tools，全部用 @Tool 编写，作为规范示例）：
  - `read_file`：读取文本文件
  - `write_file`：写入文本文件
  - `edit_file`：替换文件内指定片段
  - `bash`：执行 shell 命令
  - `glob`：按模式匹配文件路径
  - `grep`：按正则搜索文件内容
  - `search_files`：组合检索（glob + grep 封装，供 LLM 快速定位）
- **FR-2.5 安全**：命令执行做参数校验与基础注入防护（非法字符/路径穿越校验）；完整权限管理 v2 提供。

#### FR-3 Agent 循环（mycc-agent）

- **FR-3.1 消息模型**：`Message`（role / content / toolCalls / toolResult / 元数据）、`Conversation`（有序消息序列）、`Session`（会话上下文，含工作目录、模型配置、工具集）。
- **FR-3.2 循环**：调 LLM → 若返回工具调用 → 校验并执行 → 结果回填 → 再次调 LLM，直到无工具调用/达到终止条件。
- **FR-3.3 工具执行**：`ToolCallExecutor` 查 `ToolRegistry`，参数类型转换与校验，反射调用，结构化返回（含退出码/错误）。
- **FR-3.4 终止条件**：最大迭代数（可配）、用户中断、连续无工具调用后出最终回答。
- **FR-3.5 错误回填**：工具抛异常/非法参数时，错误信息回填给 LLM 令其纠正，不崩会话。
- **FR-3.6 流式输出**：**v1 即支持流式**，agent 通过 `InteractionPort` 逐段下发输出；输出事件模型与 v2 SSE 对齐。

#### FR-4 LLM 抽象（mycc-ai）

- **FR-4.1 `LlmProvider` 接口**：`chat(List<Message>, tools, options, sink)`，支持流式回调；`ModelConfig`（模型名、温度、maxTokens、baseUrl、key）。
- **FR-4.2 `MockProvider`（内置）**：离线模拟策略——关键字匹配返回预设回复，并可配置模拟场景脚本（如"用户提到 read → 触发一次模拟工具调用"），用于演示与端到端测试；**策略由实现自由发挥，可持续扩展**。
- **FR-4.3 `OpenAiCompatProvider`**：HTTP 调用 OpenAI 兼容 endpoint（可配 baseUrl 接 DeepSeek/Qwen 等），支持 stream。
- **FR-4.4 扩展**：新增 `AnthropicProvider` 仅需实现 `LlmProvider` 接口并在配置中选择。

#### FR-5 存储抽象（mycc-storage）

- **FR-5.1 `Storage` SPI**：`read(key)` / `write(key, data)` / `list(prefix)` / `delete(key)`。
- **FR-5.2 `FileStorage` 默认实现**：JSON 落盘；**会话文件包含完整消息序列，含工具调用与工具结果**，目录结构 `~/.mycc/{sessions, memory, config, projects}`。
- **FR-5.3 `ConfigService`**：加载模型/接口/安全等配置（properties/yaml），支持默认值与覆盖。

#### FR-6 CLI 界面（mycc-cli）

- **FR-6.1 交互**：JLine 提供补全、历史、多行输入、ANSI 渲染；picocli 解析命令（`start`、`tools`、`config` 等）。
- **FR-6.2 会话**：启动后进入交互 REPL，用户输入 → agent 执行 → 流式渲染；支持 `/exit`、`/clear` 等斜杠命令（v1 最小集）。
- **FR-6.3 输出渲染**：区分正文 / 工具调用 / 工具结果 / 系统提示，分色展示。

#### FR-7 UI 抽象层（独立模块 mycc-ui）

- **FR-7.1 独立 UI 模块 `mycc-ui`**：只定义 `InteractionPort` 接口与 `OutputEvent` 事件模型（面向流式设计），**不含任何渲染/显示实现**。
- **FR-7.2 具体显示在各 UI 模块实现**：`CliPort`（mycc-cli，JLine/picocli 终端渲染）与 `WebPort`（mycc-web，Jetty + SSE，v2）分别实现 `InteractionPort`，负责各自的输入采集与输出渲染。
- **FR-7.3 面向接口**：`mycc-agent` 只依赖 `mycc-ui` 的 `InteractionPort`，通过它下发事件、获取输入；不感知具体是终端还是网页。
- **FR-7.4 可插拔**：**新增界面 = 新增一个模块实现 `InteractionPort` + 在 `mycc-app` 绑定选择**；核心与 agent 零改动。

### 2.3 v2 及以后功能需求（本期仅设计，不实现）

#### FR-8 钩子系统（@Hook）

- `@Hook(event)` 注解注册；事件模型：`SessionStart/SessionEnd/ToolCallBefore/ToolCallAfter/Error/UserPromptSubmit` 等。
- `HookRegistry` 作为 BeanPostProcessor，与 `ToolRegistry` 同一机制。
- 支持同步/异步执行、失败不影响主流程（可配置）。

#### FR-9 权限管理

- 工具调用审批流：自动允许 / 自动拒绝 / 每次询问 / 按规则。
- 决策持久化（同一会话/项目记忆授权结果），结合 Storage。
- 高风险工具（bash、write_file）默认需要审批或用户确认。

#### FR-10 Memory 长期记忆

- 用户/项目/会话三层的记忆读写、注入提示词。
- 基于存储抽象；支持按关键词检索。

#### FR-11 技能（Skill）

- 注解方式：`@Skill`（能力描述 + 提示词 + 触发条件）。
- 文件方式：扫描 `SKILL.md` / skill 目录加载，作为可调用/可注入的能力。

#### FR-12 规划（Planning）

- 计划模式：先生成多步实施计划（`Plan` 步骤列表），再逐步骤执行、核对、推进。
- 可与 Subagent 结合：计划步骤分派给子代理执行。

#### FR-13 子代理（Subagent）

- 主代理可派生子代理；子代理有独立系统提示与工具子集，结果汇总回主代理。
- 基于同一条 `AgentLoop`，以不同 `Session`/上下文运行（嵌套循环）。

#### FR-14 Web 界面

- 嵌入式 Jetty + SSE：浏览器会话页，流式渲染 agent 输出。
- 复用 `InteractionPort`，实现 `WebPort`；REST 接口创建/列出/删除会话。

## 4. 架构设计

### 4.1 模块划分

```
mycc-parent (父 pom，统一版本管理)
├── mycc-core        # 自研 IoC + 注解 + 上下文 + ToolRegistry 定义（纯机制，不感知 UI）
├── mycc-ui          # UI 抽象层：InteractionPort、OutputEvent（仅接口，不含任何实现/渲染）
├── mycc-ai          # LlmProvider 接口 + MockProvider + OpenAiCompatProvider + ModelConfig
├── mycc-agent       # AgentLoop、Message/Conversation/Session、ToolCallExecutor（只依赖接口）
├── mycc-tools       # 内置工具集（@Tool 规范示例）
├── mycc-storage     # Storage SPI + FileStorage + ConfigService
├── mycc-cli         # CLI 显示实现（实现 mycc-ui 的 InteractionPort，JLine + picocli）
├── mycc-web         # Web 显示实现（实现 mycc-ui 的 InteractionPort，Jetty + SSE，v2）
└── mycc-app         # 启动器：选择并绑定某个 UI 模块，装配各模块、main 入口
```

### 4.2 依赖方向（单向、无环、可插拔）

```
mycc-app（启动器：选择并绑定某个 UI 实现）
   ├── mycc-cli ──┐
   ├── mycc-web(v2) ─> 实现 mycc-ui 的 InteractionPort（具体渲染）
   │
   ├── mycc-agent ──> mycc-core、mycc-ui（接口）、mycc-ai、mycc-tools、mycc-storage
   │
   └── 装配：把选中的 UI 实现（CliPort / WebPort）作为 InteractionPort 注入 agent
```

**各模块依赖一览（单向）：**

| 模块 | 依赖 |
| --- | --- |
| mycc-core | 无（纯机制层） |
| mycc-ui | mycc-core（必要时复用其模型类型） |
| mycc-ai / mycc-tools / mycc-storage | mycc-core |
| mycc-agent | mycc-core、mycc-ui、mycc-ai、mycc-tools、mycc-storage |
| mycc-cli / mycc-web | mycc-ui、mycc-agent |
| mycc-app | 以上全部（负责装配与选择 UI） |

- 核心与 agent **只面向接口编程**（`LlmProvider` / `Storage` / `InteractionPort`），不依赖任何具体实现。
- `mycc-core` 不依赖任何业务模块；`mycc-ui` 只含接口，不含渲染逻辑。
- **可插拔**：换界面 = 换 UI 模块（新增模块实现 `InteractionPort` + 在 `mycc-app` 绑定）；换 LLM / 存储 / 加工具同理走接口与扩展点，均不改核心。

### 4.3 关键机制设计

#### 4.3.1 自研 IoC

```
AnnotationScanner ──> BeanDefinition[] ──> BeanFactory ──> BeanPostProcessor[] ──> 实例池
```

- 扫描：读取 classpath 条目，过滤带注解类，反射读取构造器/字段依赖。
- 注入：按类型解析依赖；构造器注入优先，无构造器注入时用字段注入；未满足依赖启动期报错。
- 后处理器：bean 实例化后依次调用 `postProcessAfterInitialization`；`ToolRegistry`/`HookRegistry` 在此收集注解元数据注册。
- 生命周期：单例缓存 + `close()` 逆序销毁。

#### 4.3.2 工具注册（"写一个类 + @Tool 即可"）

```java
@Component
public class FileTools {
    @Tool(name = "read_file", description = "读取指定路径的文本文件")
    public String readFile(@ToolParam(description = "文件绝对路径") String path) { ... }
}
```

容器创建 `FileTools` bean → `ToolRegistry.postProcessAfterInitialization` 反射扫描 `@Tool` 方法 → 生成 JSON Schema → 注册 `name → ToolDefinition`。LLM 调用时由 `ToolCallExecutor` 解析、绑定参数、反射调用。

#### 4.3.3 Agent 循环

```
用户输入 → [LLM ← tools Schema] → 工具调用? ──是──> 校验/执行 → 结果回填 ──> 再次调 LLM
                                    └─否─> 输出最终回答
```
- 每一轮通过 `InteractionPort` 下发输出事件（token / tool_call / tool_result / done）。
- 迭代数超限、用户中断即终止。

#### 4.3.4 输出事件模型（为 SSE 对齐）

`OutputEvent`：`type`（token / tool_call / tool_result / status / done）+ `payload` + `sessionId` + `seq`。CLI 渲染为 ANSI 文本，Web 渲染为 SSE 帧。

#### 4.3.5 配置加载优先级

系统属性/环境变量 > 用户配置 `~/.mycc/config` > 内置默认值。

## 5. 关键流程

### 5.1 启动流程

1. `mycc-app` 解析启动参数（picocli）→ 加载配置（`ConfigService`）。
2. 初始化 `AnnotationScanner` 扫描各模块包路径 → 构建 `IocContainer`。
3. 容器装配所有 bean，注册内置工具、Hook（v2）、Port 实现。
4. 绑定 `CliPort` → 启动 REPL / 执行单次命令。

### 5.2 一次会话流程

1. CLI 采集用户输入 → 交给 `Session`。
2. `AgentLoop` 构造请求（会话消息 + 工具 Schema）→ 调 `LlmProvider`。
3. 若返回工具调用：`ToolCallExecutor` 查 `ToolRegistry` → 校验 → 执行 → 回填结果 → 循环。
4. 否则输出最终回答 → 流式渲染 → 会话结束/等待下一条输入。

## 6. 数据模型

- `Message`：`{role, content, toolCalls?, toolResult?, timestamp}`
- `Conversation`：有序 `Message[]`，可序列化落盘。
- `Session`：`{id, cwd, modelConfig, conversation, createdAt, updatedAt}`
- `ToolDefinition`：`{name, description, method, bean, parameterSchema}`
- `OutputEvent`：`{type, payload, sessionId, seq}`

### 存储目录（`~/.mycc/`）

```
~/.mycc/
├── config/          # 用户配置（config.yaml）
├── sessions/        # 会话历史 JSON（含工具调用与工具结果）
├── memory/          # 长期记忆（v2）
└── projects/        # 项目级设置（v2）
```

## 7. 分期计划

### v1 里程碑

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M1 | mycc-core：注解 + 扫描 + IoC + BeanPostProcessor | IoC 单测全绿；可用 @Component/@Inject 组装简单应用 |

| M3 | LlmProvider + MockProvider + OpenAiCompatProvider | Mock 离线跑通；配置真实 key 可接 OpenAI 兼容服务 |
| M4 | AgentLoop + ToolCallExecutor + 流式事件 | 一次"读写文件/执行命令"的完整工具循环端到端通过 |
| M5 | Storage + FileStorage + ConfigService | 会话可落盘、可恢复 |
| M6 | CliPort（JLine + picocli）+ InteractionPort | CLI 交互流畅，可扩展新界面 |

**v1 完成定义**：CLI 中输入自然语言 → Mock/真实 LLM 驱动 → 能调用内置工具 → 流式输出 → 会话落盘，全部跑通；打包为单 fat-jar 可 `java -jar` 运行。

### v2 及以后

Hook → 权限管理 → Memory → Skill → Planning → Subagent → Web（Jetty + SSE）。

## 8. 测试策略

- **mycc-core**：注解扫描、构造/字段注入、循环依赖报错、BeanPostProcessor 顺序、生命周期。
- **mycc-ai**：MockProvider 预设回复、参数构造；OpenAiCompatProvider 用 Mock WebServer 单测。
- **mycc-agent**：MockProvider 驱动的端到端（含工具调用多轮、错误回填、终止条件、流式事件序列）。
- **mycc-tools**：每个内置工具的正常/异常/边界用例。
